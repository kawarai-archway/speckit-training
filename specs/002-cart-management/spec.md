# Feature Specification: カート管理機能

**Feature Branch**: `002-cart-management`
**Created**: 2026-02-18
**Status**: Draft
**Input**: User description: "購入者が商品をカートに追加し、購入前に内容を確認・編集できる機能。購入者（buyer）ログインが必須。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - カートに商品を追加する (Priority: P1)

購入者（buyer）としてログインしたユーザーが、商品詳細ページの「カートに追加」ボタンを押して商品をカートに追加する。追加に成功するとフィードバックメッセージが表示され、ヘッダーのカートアイコンに表示される件数が更新される。

**Why this priority**: カート機能の最も基本的な操作であり、これがなければ他のカート機能が成立しない。カタログ閲覧から購入への最初のステップとなる。

**Independent Test**: 商品詳細ページから「カートに追加」ボタンを押し、成功フィードバックが表示され、カートアイコンの件数が増えることを確認する。

**Acceptance Scenarios**:

1. **Given** 購入者がログイン済みで商品詳細ページを閲覧している, **When** 在庫がある商品の「カートに追加」ボタンを押す, **Then** 商品がカートに追加され、成功フィードバックが表示され、ヘッダーのカートアイコン件数が1増える
2. **Given** 購入者がログイン済みで、すでにカートに同一商品が1個ある, **When** 同じ商品の「カートに追加」ボタンを再度押す, **Then** カート内の該当商品の数量が2に増加する
3. **Given** 購入者がログイン済みで商品詳細ページを閲覧している, **When** 在庫切れの商品を表示する, **Then** 「カートに追加」ボタンが無効化（グレーアウト）されている
4. **Given** 購入者がログイン済みで「カートに追加」ボタンを押した, **When** リクエスト処理中に再度ボタンを押す, **Then** 二重送信が防止され、商品は1回分のみ追加される

---

### User Story 2 - カート内容を確認する (Priority: P1)

購入者がカートページを開き、追加した商品の一覧を確認する。各商品の画像・商品名・単価・数量・小計が表示され、合計金額（商品合計・消費税・総合計）が確認できる。

**Why this priority**: 購入者が購入判断を下すために不可欠な情報表示であり、カート追加と同様に基本機能。

**Independent Test**: カートに商品を追加した後、カートページを開いて商品情報と合計金額が正しく表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに商品が1個以上ある状態で, **When** カートページを開く, **Then** 各商品の画像・商品名・単価・数量・小計が一覧表示され、商品合計・消費税（10%、端数切り捨て）・総合計が表示される
2. **Given** カートに単価1,000円の商品が3個、単価500円の商品が2個ある, **When** カートページを開く, **Then** 商品合計4,000円、消費税400円、総合計4,400円が表示される
3. **Given** カートが空の状態で, **When** カートページを開く, **Then** 「カートに商品がありません」メッセージと商品一覧ページへのリンクが表示される

---

### User Story 3 - カート内の数量を変更する (Priority: P2)

購入者がカートページで商品の数量を変更すると、小計と合計金額が即時に更新される。

**Why this priority**: 購入数の調整は購入前の重要な操作だが、カート追加と内容確認が先に必要。

**Independent Test**: カートページで商品の数量を変更し、小計・合計が即時に正しく再計算されることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに単価1,000円の商品が1個ある, **When** 数量を3に変更する, **Then** 小計が3,000円に更新され、合計金額（税込）も即時再計算される
2. **Given** カートに在庫数5の商品がある, **When** 数量を6に変更しようとする, **Then** 変更が拒否され、在庫数を超えている旨のエラーメッセージが表示される
3. **Given** カートに商品がある, **When** 数量を0以下または100以上に変更しようとする, **Then** 変更が拒否される（数量は1〜99の範囲に制限される）

---

### User Story 4 - カートから商品を削除する (Priority: P2)

購入者がカートページで不要な商品を削除できる。削除前に確認ダイアログで意図を確認する。

**Why this priority**: カート編集の基本操作だが、数量変更と同等の優先度。

**Independent Test**: カートページで商品の削除ボタンを押し、確認ダイアログで「はい」を選択すると商品がカートから削除されることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに商品が2個以上ある, **When** 1つの商品の削除ボタンを押し確認ダイアログで「はい」を選択する, **Then** 該当商品がカートから削除され、合計金額が再計算される
2. **Given** カートに商品が2個以上ある, **When** 削除ボタンを押し確認ダイアログで「いいえ」を選択する, **Then** 商品は削除されずカート内容は変わらない
3. **Given** カートに商品が1個だけある, **When** その商品を削除する, **Then** カートが空になり「カートに商品がありません」メッセージと商品一覧への導線が表示される

---

### User Story 5 - 未ログイン時のカート追加リダイレクト (Priority: P2)

未ログインのユーザーが「カートに追加」ボタンを押すと、ログインページにリダイレクトされる。ログイン完了後、元の商品詳細ページに自動的に戻る。

**Why this priority**: セキュリティとUXの両面で重要だが、ログイン済みユーザーのフローが先に確立される必要がある。

**Independent Test**: 未ログイン状態で「カートに追加」を試み、ログインページへの遷移とログイン後の復帰を確認する。

**Acceptance Scenarios**:

1. **Given** 未ログイン状態で商品詳細ページを閲覧している, **When** 「カートに追加」ボタンを押す, **Then** ログインページにリダイレクトされる
2. **Given** 未ログイン状態で商品Aの詳細ページから「カートに追加」を試みてログインページにリダイレクトされた, **When** 購入者（buyer）として正常にログインする, **Then** 商品Aの詳細ページに戻る

---

### User Story 6 - カート内容の永続化 (Priority: P3)

カートに追加した商品はページ遷移やブラウザリロード後も保持される。

**Why this priority**: ユーザー体験の安定性に寄与するが、基本操作が先に確立される必要がある。

**Independent Test**: カートに商品を追加した後、ページ遷移やブラウザリロードを行い、カート内容が保持されていることを確認する。

**Acceptance Scenarios**:

1. **Given** カートに商品が追加されている, **When** 別のページに遷移してからカートページに戻る, **Then** カート内容がそのまま保持されている
2. **Given** カートに商品が追加されている, **When** ブラウザをリロードする, **Then** カート内容がそのまま保持されている

---

### Edge Cases

- カートに同一商品を繰り返し追加して数量が99に達した場合、それ以上の追加は拒否される
- カートに入れた商品が他のユーザーの購入により在庫切れになった場合、カートページ表示時に在庫状況を反映する
- 消費税計算で端数が発生する場合、切り捨てで処理する（例: 商品合計999円 → 消費税99円）
- 複数商品の消費税は合計金額に対して一括計算する（商品ごとではない）
- カートに商品が入った状態でログアウトした場合、再ログイン後のカート内容の扱い（インメモリのため、サーバー側で保持される）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 購入者（buyer）としてログイン済みのユーザーは、商品詳細ページの「カートに追加」ボタンで商品をカートに追加できること
- **FR-002**: 同一商品を再度カートに追加した場合、新しいカート項目を作成せず既存の数量を1増加させること
- **FR-003**: 在庫切れの商品は「カートに追加」ボタンを無効化し、操作できないこと
- **FR-004**: 「カートに追加」ボタンは処理完了まで無効化し、二重送信を防止すること
- **FR-005**: カート追加成功時にユーザーへフィードバックメッセージを表示すること
- **FR-006**: カート追加・削除・数量変更時にヘッダーのカートアイコン横の件数表示を更新すること
- **FR-007**: 未ログインユーザーがカート操作を試みた場合、ログインページにリダイレクトすること
- **FR-008**: ログイン後、リダイレクト元のページに自動的に戻ること
- **FR-009**: カートページで各商品の画像・商品名・単価・数量・小計を一覧表示すること
- **FR-010**: カートページで商品合計・消費税（10%、端数切り捨て）・総合計を表示すること
- **FR-011**: 消費税は商品合計金額に対して一律10%を適用し、小数点以下を切り捨てること
- **FR-012**: カートが空の場合、「カートに商品がありません」メッセージと商品一覧ページへの導線を表示すること
- **FR-013**: カート内の商品数量を1〜99の範囲で変更でき、在庫数を上限とすること
- **FR-014**: 在庫数を超える数量への変更時にエラーメッセージを表示すること
- **FR-015**: 数量変更時に小計・合計金額を即時に再計算・表示すること
- **FR-016**: カートから商品を削除する前に確認ダイアログを表示すること
- **FR-017**: 確認ダイアログで承認した場合のみ商品を削除すること
- **FR-018**: カート内容はページ遷移・ブラウザリロード後も保持されること
- **FR-019**: カートの永続化はインメモリ（サーバーサイド）で行うこと

### Key Entities

- **カート (Cart)**: 購入者ごとに1つ存在するカート。購入者ID、カート項目のコレクション、作成日時を持つ
- **カート項目 (CartItem)**: カート内の1商品を表す。商品ID、数量を持ち、カタログの商品情報（商品名・単価・画像・在庫数）を参照する
- **商品 (Product)**: カタログ機能で管理される既存エンティティ。商品名・単価・画像・在庫数を含む（カタログ機能に依存）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 購入者が商品詳細ページからカートに商品を追加する操作を3秒以内に完了でき、即座にフィードバックを受け取れること
- **SC-002**: カートページで商品合計・消費税・総合計が常に正確に計算・表示されること（消費税10%、端数切り捨て）
- **SC-003**: 購入者がカート内の数量変更を行った際、1秒以内に合計金額が再計算されること
- **SC-004**: 未ログインユーザーがカート操作を試みた場合、100%ログインページにリダイレクトされ、ログイン後に元のページに戻れること
- **SC-005**: ページ遷移・ブラウザリロード後にカート内容が100%保持されること
- **SC-006**: 二重送信防止により、同一操作が重複して処理されないこと

## Assumptions

- カタログ機能（商品一覧・商品詳細）は実装済みで、商品データ（ID、名前、単価、画像、在庫数）が利用可能
- 購入者（buyer）ロールによるログイン・認証機能は実装済みまたは同時に利用可能
- 消費税は一律10%で軽減税率は対象外。税計算は商品合計金額に対して一括で行う
- カートの永続化はインメモリ（サーバーサイド）とし、データベース永続化は将来フェーズで対応
- 1購入者につきカートは1つのみ存在する
- カート追加時の数量は1固定（数量指定はカートページでのみ行う）
