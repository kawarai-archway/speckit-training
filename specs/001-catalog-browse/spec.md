# 機能仕様書: カタログ閲覧機能

**Feature Branch**: `001-catalog-browse`
**Created**: 2026-02-13
**Status**: Draft
**Input**: ユーザー説明: "購入者が商品カタログを閲覧できる機能。認証不要で閲覧可能。商品一覧表示、商品詳細表示、商品検索。"

## ユーザーシナリオ & テスト *(必須)*

### ユーザーストーリー 1 - 商品一覧表示 (優先度: P1)

購入者がカタログページにアクセスすると、公開中の商品一覧がカード形式で表示される。各カードには商品画像・商品名・価格・在庫状況が表示される。1ページあたり12件表示され、12件を超える場合はページネーションで次ページに移動できる。認証なしで閲覧可能。

**この優先度の理由**: 商品一覧はカタログ閲覧の最も基本的な機能であり、これだけで購入者に商品情報を提供できる MVP となる。

**独立テスト**: 商品一覧ページにアクセスし、商品カードが12件表示されること、ページネーションで次ページに遷移できること、在庫切れ商品に「在庫切れ」ラベルが表示されることを確認すれば、このストーリー単体で検証可能。

**受入シナリオ**:

1. **Given** 公開中の商品が5件登録されている, **When** 購入者がカタログページにアクセスする, **Then** 5件の商品カードが表示され、各カードに商品画像・商品名・価格・在庫状況が含まれる
2. **Given** 公開中の商品が15件登録されている, **When** 購入者がカタログページにアクセスする, **Then** 最初の12件が表示され、ページネーションコントロールが表示される
3. **Given** 公開中の商品が15件登録されている, **When** 購入者がページ2に移動する, **Then** 残りの3件が表示される
4. **Given** 在庫数が0の商品がある, **When** 購入者がカタログページにアクセスする, **Then** その商品カードに「在庫切れ」と表示される
5. **Given** 公開中の商品が0件, **When** 購入者がカタログページにアクセスする, **Then** 「商品がありません」というメッセージが表示される
6. **Given** 商品画像が未設定の商品がある, **When** 購入者がカタログページにアクセスする, **Then** その商品カードにプレースホルダー画像が表示される

---

### ユーザーストーリー 2 - 商品詳細表示 (優先度: P2)

購入者が商品一覧から特定の商品を選択すると、商品詳細画面に遷移する。詳細画面では商品画像・商品名・価格・説明文・在庫数が表示され、「カートに追加」ボタンが配置される。在庫切れの場合はカート追加ボタンが無効化される。

**この優先度の理由**: 商品詳細は一覧に次いで重要な機能であり、購入判断に必要な詳細情報の確認とカート追加アクションを提供する。一覧表示に依存するが、独立して実装・テスト可能。

**独立テスト**: 商品詳細ページに直接アクセスし、商品情報（画像・名前・価格・説明文・在庫数）が正しく表示されること、カート追加ボタンの活性/非活性状態が在庫に応じて切り替わることを確認すれば検証可能。

**受入シナリオ**:

1. **Given** 在庫ありの公開商品が存在する, **When** 購入者が商品詳細画面にアクセスする, **Then** 商品画像・商品名・価格・説明文・在庫数が表示され、「カートに追加」ボタンが有効状態で表示される
2. **Given** 在庫数が0の公開商品が存在する, **When** 購入者が商品詳細画面にアクセスする, **Then** 商品情報が表示され、「カートに追加」ボタンが無効化（disabled）されている
3. **Given** 商品画像が未設定の商品が存在する, **When** 購入者が商品詳細画面にアクセスする, **Then** プレースホルダー画像が表示される
4. **Given** 存在しない商品IDが指定された, **When** 購入者が商品詳細画面にアクセスする, **Then** 適切なエラーメッセージが表示される

---

### ユーザーストーリー 3 - 商品検索 (優先度: P3)

購入者がカタログページでキーワードを入力して検索すると、商品名または説明文にキーワードを含む商品が一覧表示される。検索結果が0件の場合は適切なメッセージを表示する。検索条件をクリアすると全商品一覧に戻る。

**この優先度の理由**: 検索は商品数が増えた際に利便性を向上させる機能であり、一覧表示が動作していることが前提となる。一覧・詳細が完成した上で追加価値を提供する。

**独立テスト**: カタログページの検索フィールドにキーワードを入力し、該当商品のみが表示されること、該当なしの場合にメッセージが表示されること、クリアで全件表示に戻ることを確認すれば検証可能。

**受入シナリオ**:

1. **Given** 商品名に「りんご」を含む商品が2件登録されている, **When** 購入者が「りんご」で検索する, **Then** 該当する2件の商品のみが表示される
2. **Given** 説明文に「オーガニック」を含む商品が1件登録されている, **When** 購入者が「オーガニック」で検索する, **Then** 該当する1件の商品が表示される
3. **Given** 「存在しないキーワード」に該当する商品がない, **When** 購入者がそのキーワードで検索する, **Then** 「該当する商品がありません」というメッセージが表示される
4. **Given** 検索結果が表示されている, **When** 購入者が検索条件をクリアする, **Then** 全商品一覧が再表示される

---

### エッジケース

- ページネーションのページ番号に不正な値（0、負数、存在しないページ番号）が指定された場合、1ページ目にフォールバックする
- 商品名が非常に長い場合（200文字上限）、カード上で適切に省略表示される
- 検索キーワードが空文字の場合、全商品一覧が表示される
- 価格が0円の商品は「¥0」と正しく表示される
- 同時に複数タブからアクセスしても正常に動作する

## 要件 *(必須)*

### 機能要件

- **FR-001**: システムは公開中（published）の商品一覧をカード形式で表示しなければならない。各カードには商品画像・商品名・価格・在庫状況を含める
- **FR-002**: システムは1ページあたり12件の商品を表示しなければならない
- **FR-003**: 商品が12件を超える場合、システムはページネーションコントロールを表示し、ページ間の移動を可能にしなければならない
- **FR-004**: 在庫数が0の商品について、システムは「在庫切れ」ラベルを表示しなければならない
- **FR-005**: 商品が0件の場合、システムは「商品がありません」メッセージを表示しなければならない
- **FR-006**: システムは商品詳細画面で商品画像・商品名・価格・説明文・在庫数を表示しなければならない
- **FR-007**: 在庫がある商品の詳細画面に「カートに追加」ボタンを有効状態で表示しなければならない。ボタン押下時は Cart ドメインの API を呼び出す（カート機能自体の実装は本スコープ外）
- **FR-008**: 在庫切れの商品の詳細画面では「カートに追加」ボタンを無効化（disabled）しなければならない
- **FR-009**: 商品画像が未設定の場合、システムはプレースホルダー画像を表示しなければならない
- **FR-010**: システムはキーワードによる商品検索機能を提供しなければならない。検索対象は商品名および説明文とする
- **FR-011**: 検索結果が0件の場合、システムは「該当する商品がありません」メッセージを表示しなければならない
- **FR-012**: 検索条件のクリア操作により、全商品一覧に戻らなければならない
- **FR-013**: カタログ閲覧機能は認証不要でアクセス可能でなければならない
- **FR-014**: 一覧表示では公開中（published）の商品のみを表示し、draft・archived ステータスの商品は表示しない

### 主要エンティティ

- **商品（Product）**: 商品カタログの基本エンティティ。属性: 商品ID、商品名、価格、説明文、商品画像URL、在庫数、ステータス（公開中/下書き/アーカイブ）、作成日時、更新日時

### スコープ外

- カート機能自体の実装（「カートに追加」ボタンの UI 配置と API 呼び出しのみ本スコープ）
- カテゴリフィルタ機能
- ソート機能（価格順、新着順等）
- 管理者向け商品管理（CRUD）機能

### 前提条件

- 商品データは事前にシステムに登録済みであること（シードデータ）
- 既存の Product エンティティに在庫数（stock）フィールドが存在しないため、実装時にデータモデルを拡張する必要がある
- 既存の商品一覧取得に検索（keyword）パラメータが存在しないため、実装時にデータモデルを拡張する必要がある

## 成功基準 *(必須)*

### 測定可能な成果

- **SC-001**: 購入者がカタログページにアクセスしてから商品一覧が表示されるまで3秒以内であること
- **SC-002**: 購入者が任意の商品の詳細情報に2クリック以内でアクセスできること（一覧→詳細）
- **SC-003**: キーワード検索の結果が表示されるまで2秒以内であること
- **SC-004**: 在庫切れ商品を識別可能な視覚表示が提供され、購入者が在庫状況を即座に判断できること
- **SC-005**: 商品が0件・検索結果が0件の場合に、購入者が状況を理解できる明確なメッセージが表示されること
- **SC-006**: ページネーションにより、購入者が全商品を漏れなく閲覧できること（12件ずつ）
